## 0. 이 문서를 읽는 법

상위 기획서는 **3D 3인칭**을 전제로 작성됐다. 2D로 내리면 일부 시스템이 그냥 옮겨지지 않고 **재설계가 필요하다.** 1장이 그 목록이고, 2장부터가 실제 아트 명세다.

각 항목에는 상위 문서의 참조 번호(예: `→ 8.0`)를 달았다. 기획 변경이 필요한 항목은 **⚠ 기획 파급**으로 표시했다.

## 1. 3D → 2D 전환 판단

### 1.1 시점 결정 — 탑다운 3/4 뷰 (4방향)

| 후보 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **탑다운 3/4 뷰** | 타일맵 오소링 최속, 미니맵이 곧 월드, 4방향만 그리면 됨, 2인 운반·대열 표현 자연스러움 | 실내 벽 표현에 지붕 페이드 필요 | **채택** |
| 아이소메트릭 | 입체감, 병영 건물이 멋있음 | 스프라이트 물량 ×1.5, Y-sort 지옥, 타일 제작비 급증 | 기각 |
| 사이드뷰 | 애니메이션 가장 저렴 | 연병장·행군·수색 같은 **평면 이동**이 표현 불가 | 기각 |

**결정: 탑다운 3/4 뷰, 4방향(정면/후면/측면 1종 + 미러링).**
근거는 이 게임의 핵심 동사가 전부 **평면 이동과 지점 상호작용**이라는 것이다 — 창고에서 물건을 꺼내 부서로 옮기고(공통 일과 6.1), 두 지점의 밸브를 동시에 조작하고(8.0), 대열을 유지하며 행군한다(9.0). 전부 XY 평면 문제다.

### 1.2 2D 전환이 해결하는 것

| 항목 | 3D에서의 문제 | 2D에서 |
|---|---|---|
| **캐릭터 애니메이션** | ARCH-01이 Unity를 쓰는 **1순위 근거**로 든 항목. Humanoid 리타게팅·IK 필요 | 스프라이트 시트. 제작비가 1/5 이하 |
| **4인 야외 60fps** (18.0 · 완화 불가 항목) | 최대 리스크. M0 게이트의 존재 이유 | 사실상 해소. 2D 스프라이트 4인 + 타일맵은 저사양에서도 여유 |
| **100분 힙 안정성** (18.0 · 완화 불가) | 탭 크래시 위험 | 메모리 예산 1/4 이하. 여전히 프로파일링은 하되 리스크 등급 하향 |
| **초기 다운로드 120MB** | 로비 프리페치로 겨우 흡수 | **≤ 25MB 복원 가능.** 초안의 25MB 예산이 되살아난다 |
| **모바일 제외** (ARCH-03) | 성능 때문에 포기 | 성능상으로는 가능. 다만 **UI 정보 밀도 때문에** 여전히 제외 권장 |

> **⚠ 기획 파급 — 19.0 로드맵 재작성 필요**
> M0의 성능 게이트(4주, "WebGL에서 4인 100분이 버티느냐")는 2D에서 **1주 스모크 테스트로 축소**된다.
> 19.0의 축소 순위표(파티클 → 맵 → 배경 NPC → **인원 4→3**)도 발동 가능성이 매우 낮아진다.
> 확보된 3주는 **훈련 맵 9종(M3)** 쪽으로 재배분할 것을 권장한다 — 2D에서 병목은 성능이 아니라 **콘텐츠 물량**으로 이동한다.

### 1.3 ⚠ 2D 전환이 **깨뜨리는** 것 — 반드시 재설계

#### (1) 통신병 시스템의 긴장이 소멸한다 — 최우선 문제

3D 3인칭에서는 벽 너머가 안 보이므로 "무전 두절 → 물리적으로 모여야 정보가 전달된다"(8.0 COMM-01)가 성립했다. **2D 탑다운은 기본적으로 화면 안이 전부 보인다.** 무전이 끊겨도 분대원이 어디서 뭘 하는지 눈으로 보이면, 통신병이라는 보직 하나가 통째로 무의미해진다.

**해결안 3종 (택1 또는 병용):**

| 안 | 구현 | 효과 | 비용 |
|---|---|---|---|
| **A. 구역 단위 시야 차단** | 부대를 논리 구역(생활관/연병장/창고/식당/초소…)으로 분할. **다른 구역의 분대원 스프라이트를 렌더하지 않음.** 카메라는 자기 구역만 따라감 | 원안의 긴장을 거의 그대로 복원. 구현 단순 | **낮음 · 권장** |
| B. 소프트 안개 | 캐릭터 반경 밖을 Light2D 마스크로 어둡게. 실루엣만 보임 | 분위기 좋음. 실내에서 효과 약함 | 중 |
| C. 미니맵 전용 정보화 | 월드는 다 보이되 **분대원 위치·퀘스트 핑을 미니맵에서만** 제공하고, 미니맵을 무전 연결 시에만 활성 | 가장 저렴. 다만 "눈으로 보면 되잖아"가 남음 | 낮음 |

> **채택 권장: A + C 병용.** 구역 밖은 안 보이고(A), 미니맵으로도 안 보인다(C). 무전이 살아 있으면 미니맵에 아군 마커와 통신병 핑이 뜬다. 무전이 끊기면 미니맵이 회색으로 죽고, 정보를 얻으려면 그 구역으로 걸어가야 한다.
> **부수 이득**: 구역 단위 렌더는 성능·메모리에도 유리하고, 15.0의 "M — 부대 지도"에 실질적 용도를 준다.

#### (2) 행군 대열 유지 (9.0 · D-08)

3D에서는 앞 사람과의 거리를 3인칭 시점으로 체감했다. 2D 탑다운에서 20km를 걷게 하면 그냥 지루한 이동이 된다.

**재설계: 횡스크롤 레인 미니게임으로 전환.**
- 행군 구간에만 카메라를 **사이드뷰로 전환**(전용 씬). 4명이 좌→우로 자동 전진
- 각자 **페이스 게이지**를 유지 — 너무 앞서면 체력 과소모, 뒤처지면 대열 이탈 판정
- 낙오자 발생 시 좌우 인접 2인이 접근해 **부축 상태**로 전환(공동 부하 패턴)
- 구간 4개 = 체크포인트 4개 = 필수 퀘스트 4건 (9.0 TRN-02 카운트 규칙 그대로 적용)

> 이 씬만 사이드뷰인 것은 문제가 되지 않는다 — 오히려 **행군일의 이질감**이 연출이 된다. 유격(D-12/13)의 릴레이 코스도 같은 사이드뷰 씬을 재활용할 수 있다.

#### (3) 화생방 방독면 착용 9초 (9.0 · D-05)

3D에서는 시야창이 좁아지는 것이 압박이었다. 2D에서 시야를 좁히면 그냥 안 보인다.

**재설계:**
- 착용 미니게임 자체는 **정면 클로즈업 컷인 오버레이**로 처리 (마스크 끈 → 조임 → 밀폐 확인, 3단계 QTE)
- 착용 후 압박은 **화면 프레임 오버레이**(고무 마스크 실루엣이 화면 가장자리 20%를 덮음) + 호흡음 + 수분 소모 2배
- 8.0의 "자유 채팅 입력 차단, 퀵 커맨드만" 규칙은 그대로 유지 — 2D에서도 완벽히 성립한다

#### (4) 열 왜곡 · 결빙 · 야시장비 (5.0 · 16.0)

URP Volume 프로파일에 의존하던 6밴드 룩. **2D Renderer도 Volume을 지원**하므로 Color Adjustments / Vignette / Bloom은 그대로 쓸 수 있다. 열 왜곡만 풀스크린 셰이더로 직접 구현해야 한다(6.4 참조). **손실 없음.**

#### (5) 1인칭 전환 (표지 사양)

**삭제.** 2D에서 대응물이 없고, 기획서 본문 어디에서도 1인칭이 필요한 시스템이 없다. 사격 조준(9.0)만 1인칭을 암시하는데, 이는 **조준 오버레이 미니게임**으로 대체한다(6.3.9).

## 2. 화면 · 카메라 규격

### 2.1 하이브리드 해상도 (핵심 결정)

이 게임은 **정보 밀도가 매우 높다** — 6스탯, 4분할 수첩, 하달 드래그 UI, 18일 커리큘럼 표. 저해상도 픽셀 UI로는 담을 수 없다. 반대로 월드를 고해상도 벡터로 그리면 제작비가 폭발한다.

**결정: 월드는 픽셀아트, UI는 네이티브 해상도.**

| 레이어 | 렌더 방식 | 규격 |
|---|---|---|
| **월드** (타일맵·캐릭터·VFX) | 픽셀 퍼펙트 | 논리 해상도 **640 × 360**, 정수배 업스케일 |
| **UI** (HUD·창·메뉴) | Screen Space Overlay | 레퍼런스 **1920 × 1080**, 벡터/고해상도 비트맵 |

- **PPU (Pixels Per Unit): 32**
- **Orthographic Size**: `360 / 2 / 32 = 5.625`
- **Pixel Perfect Camera 설정**: Assets PPU `32` / Reference Resolution `640 × 360` / **Upscale Render Texture ON** / Pixel Snapping ON / Crop Frame `None` (레터박스 없이 스트레치 대신 정수배 + 여백은 월드로 채움)
- 지원 배율: ×2 (1280×720), ×3 (1920×1080, 기준), ×4 (2560×1440). 그 사이 해상도는 정수배 + 오버스캔

### 2.2 카메라 동작

| 상황 | 동작 |
|---|---|
| 평시 | 플레이어 추적, **데드존 96×54px**, SmoothDamp 0.15s |
| 구역 경계 | Cinemachine Confiner 2D — 구역 밖으로 나가지 않음 (1.3의 시야 차단과 동일 경계 사용) |
| 하달 창 / 점호 판정 | 카메라 고정, 월드 위에 **암전 60%** 오버레이 |
| 행군 · 유격 | 사이드뷰 씬. 자동 좌→우 스크롤 |
| 후송 | 쓰러진 지점으로 0.5s 팬 → 1.5s 정지 → 의무실로 컷 |

## 3. 아트 디렉션

### 3.1 컨셉 한 줄

> **"군용 등사판 서류 위에 놓인 저채도 픽셀 병영."**

상위 기획서(SAD-GDD-001)의 문서 디자인 자체를 게임의 UI 톤으로 승격시킨다. 갱지색 바탕, 잉크색 글자, 올리브 강조선, 모노스페이스 숫자, 얇은 괘선. 플레이어가 보는 HUD가 **실제 부대에서 쓰는 서류처럼** 보이게 하는 것이 목표다.

월드는 그 서류가 기록하고 있는 대상 — 저채도 픽셀 병영. 화려하지 않고, 콘크리트와 흙과 올리브색이 대부분이며, **색이 튀는 순간은 오직 온도 밴드가 바뀔 때**다.

### 3.2 3원칙

1. **실루엣 우선.** 32×48 픽셀에서 디테일은 읽히지 않는다. 4보직은 **머리 실루엣**(전투모/헤드셋/적십자완장/서류판)으로 즉시 구분되어야 한다.
2. **색은 정보다.** 장식적 채색을 금지한다. 채도가 높은 색은 전부 의미를 갖는다 — 청색=한랭, 주황=고온, 적색=경고, 올리브=상호작용 가능.
3. **UI는 종이, 월드는 픽셀.** 두 레이어를 섞지 않는다. UI 안에 픽셀 아이콘을 넣을 때는 명시적으로 ×3 배율 정수 스케일로만 배치한다.

### 3.3 금지 사항 (20.0 소재 감수성 연동)

- 폭력·구타·인신공격 묘사 일절 금지. 처벌은 **게이지 감소와 추가 일과 카드**로만 표현
- 유혈 표현 없음. 부상은 **흰 붕대 스프라이트 + 스탯 게이지**로만
- 실존 부대명·부대마크·계급장 실물 도안 사용 금지 → **가상 도안**으로 대체 (4.6 참조)
- 후송·쓰러짐 연출에 신체 고통 묘사를 넣지 않는다. 화면 채도 저하 + 페이드로 추상화

> - `legs` `torso`: 전 클립 필요. 변형 각 4종 → 4 × 263 × 2 ≈ **2,100장** ← **여기가 진짜 병목**

>
> **최종 물량 목표: 약 1,000 프레임.** 픽셀 아티스트 1명 기준 8~10주.

#### 7.1.5 중앙 하단 — 상호작용 프롬프트 (→ 15.0)

480 × 88, y = 880. 컨텍스트 표시.

│  [E]  난로 밸브 조작                 │   ← 1행: 키 + 행동명 (22px)

#### 7.1.6 좌상단 — 알림 스택

퀘스트 배정 / 완료 / 돌발 발생 / 군기 변동 / 하달 수신. 카드 380 × 64, 최대 4개 스택, 각 4초 후 페이드. 우→좌 슬라이드 인.

### 7.8 퀵 커맨드 라디얼 (→ 8.0) — 주 소통 수단

**보이스가 없으므로 이것이 소통의 전부다.** 8종이 서로 확실히 구분되는 것이 8.0의 성립 조건.

- **입력**: `Q` 홀드 → 라디얼 표시 → 마우스 방향 → 릴리즈 발신. 또는 `Q` + 숫자 1~8 즉시 발신
- **표시 지연 0ms** — 홀드 즉시 표시. 타임 프레셔 구간에서 쓰이므로 애니메이션 금지
- 라디얼 지름 360px, 슬롯 8개 각 96 × 96

| # | 커맨드 | 아이콘 | 색 | SFX 성격 | 방향(기본) |
|---|---|---|---|---|---|
| 1 | 집합 | 모이는 화살표 ×3 | `accent` | 짧은 호루라기 2음 | ↑ |
| 2 | 대기 | 손바닥 | `ink-2` | 낮은 단음 | ↗ |

### 13.2 제작 우선순위 (마일스톤 대응)

| 단계 | 아트 산출물 | 검증 질문 |
|---|---|---|
| **M0** (코어) | 캐릭터 베이스 1종 + `idle`/`walk` 4방향 · 부대 구역 3개(`Z01` 생활관 / `Z02` 복도 / `Z11` 연병장) · **HUD 시간대 바 + 컨디션 링** · 점호 판정 화면 | 하루 판정 구조만으로 재미가 있나? |
| **M1** (협동) | `walk_coop` `work_*` · 퀵 커맨드 라디얼 + 아이콘 8 + SFX 8 · 수첩 4분할 · **구역 시야 차단 구현** | 혼자 못 깨는 구조가 긴장으로 읽히나? **무전 두절이 실제로 압박이 되나?** |
| **M2** (환경) | **Volume Profile 7종 + 셰이더 6종** · 파티클 12 · `TS_Snow` · 상태 이상 애니메이션(`shiver` `pant`) | 기온이 바뀐 것을 말 안 해줘도 알아채나? |
| **M3** (콘텐츠) | 훈련 맵 10종 · 사이드뷰 씬(행군·유격) · 방독면 컷인 · **하달 창** · 일과표 화면 | 18일이 지루한 구간 없이 이어지나? |
| **M4** (완성도) | 보직 4종 피복·완장·계급장 전체 · 승급 심사 화면 · 후송 연출 · 하달 장부 · 접근성 옵션 | 보직마다 다시 플레이할 이유가 있나? |
| **M5** (출시) | 엔딩 리포트 3분기 · BGM 6 · 폴리싱 · Addressables 번들 분할 | 완주율이 15~25%에 들어오나? |

> **M1의 검증 질문에 한 줄이 추가된 것**에 주의. 2D 전환의 최대 리스크는 성능이 아니라 **통신병 시스템의 무력화**(1.3-1)이며, 그 검증을 M1에서 반드시 해야 한다. M3까지 미루면 되돌릴 수 없다.
