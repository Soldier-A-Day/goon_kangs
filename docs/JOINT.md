# 합동 퀘스트 — 판 하나를 인원이 나눠 채운다

QST-01의 목적은 한 줄이다. **한 명이 잘해서 캐리하는 구조를 물리적으로 막는다.**

## 무엇을 고를 수 있었나

합동을 미니게임으로 만드는 방법이 셋 있었다.

**1. 각자 제 판을 통과한다.** 구현이 제일 쉽다. 그런데 이건 협동이 아니라
같은 숙제를 네 명이 따로 하는 것이다 — 옆 사람이 무엇을 하든 내 화면은 안 바뀐다.

**2. 판 하나를 실시간으로 공유한다.** 같은 격자를 여럿이 동시에 만진다.
가장 그럴듯하지만 **판 상태를 서버가 소유해야 한다.** 지금 서버는 원형 로직을
전혀 모르고("판을 도는 것은 클라이고, 여기에 판정은 없다"), 14종을 sim에 다시
구현해야 한다. 10Hz 스냅샷에 격자 상태를 실어 나르는 문제도 따라온다.

**3. 목표를 조각으로 쪼개 같이 채운다.** ← 이걸 골랐다.

3번이 협동인 이유는 **조각 통이 하나**이기 때문이다. 누가 채우든 같은 칸에
쌓이고, 남이 채운 것이 내 화면에서도 찬다. 그리고 인원이 모자라면 한 조각도
안 오른다 — 캐리를 막는 것은 이 규칙 하나면 충분하다.

서버가 아는 것은 **조각 수 하나뿐**이다. 한 조각이 무엇인지(불일치 1건 ·
물건 1개 · 구간 하나)는 원형이 알고, 서버로는 "하나 채웠다"만 올라온다.
그래서 원형 14종을 서버에 다시 만들 필요가 없다.


## 배정 — 합동 17건

전용 원형을 새로 만들지 않았다. 창고 재물조사는 `AUDIT`이고 하역 릴레이는
`MASH`다. 개인 일과와 **다른 것은 누가 채우는가뿐**이다.

**조각 수를 인원의 3~4배로 잡았다.** 인원과 같게 두면 한 사람이 다 채울 수
있고, 그러면 나머지는 서 있기만 하는 대기가 된다. 협동은 "같이 해야 끝난다"가
아니라 "혼자 하면 시간이 모자란다"로 만들어야 성립한다.

정의는 `packages/sim/data/quests.json`의 `joint.boards`에 있다. `steps`가 조각
수이고 나머지는 원형 파라미터다 — 개인 일과와 같은 표를 쓴다.


## 서버 — 조각만 센다

`packages/sim/src/step.ts`

```
addJointStep(state, memberId, questId)
  ├ 합동인가 · 잠기거나 끝나지 않았는가
  ├ canWork()      구역 · 시간대 · 이동중 — `interact`와 같은 관문
  ├ actorsAt() >= minActors        ← 여기가 강제 협동
  └ jointDone += 1, 다 차면 complete()
```

**요구 인원이 그 자리에 없으면 그냥 무시한다.** 거절 메시지를 보내지 않는다 —
게이지가 안 오르는 것 자체가 신호이고, 화면이 그 이유를 읽어 준다(§7.1.5).

`Quest`에 필드 둘이 늘었다.

| | |
|---|---|
| `jointTotal` | 목표 조각 수. 합동이 아니면 0 |
| `jointDone` | 분대가 채운 조각 |

### 대리도 채운다

`tickJointProxies()`

ROLE-03이 1~3인 방을 성립시키려면 대리가 실제로 기여해야 한다. 예전에는
합동이 시간으로 찼으므로 대리가 머릿수만 채우면 됐는데, 조각을 채워야 하는
지금은 그것만으로 부족하다.

다만 **사람보다 느리다.** 소요 시간을 꽉 채워야 한 사람 몫(`jointTotal /
minActors`)이고, 사람은 판을 돌려 그보다 빨리 채운다. "대리는 생존은
시켜주지만 성장은 시켜주지 않는다"가 여기서도 같다.

조각은 정수라 한 틱에 0.3개씩 올릴 수 없어서, 떨어질 만큼 모일 때까지
`RunState.jointProxyMs`에 쌓아 둔다. 이게 없으면 틱이 잘게 오는 서버에서
대리가 영영 기여를 못 한다.

### 완료에는 등급이 없다

개인 일과는 `questCleared`가 등급(A/B/C)을 싣고 오지만, 합동은 `grade`가
`null`이다. 분대가 같이 채운 것을 개인 등급으로 가를 수 없다.


## 프로토콜

```
intent   jointStep { questId }
snapshot quests[].jointTotal · quests[].jointDone
```

`jointStep`에는 조각 수가 없다 — **한 번에 하나씩만** 올라온다. 클라가 "다섯 개
채웠다"를 보낼 수 있으면 조작 여지가 그만큼 커진다.

`jointDone`이 스냅샷에 실리는 것이 이 설계의 핵심이다. 남이 채운 조각이 내
화면에서도 차야 협동으로 읽힌다.


## 클라 — `JointBoard`

`unity/Assets/Scripts/Net/Minigame/JointBoard.cs`

`InterruptBoard`와 같은 방식으로 **겉을 한 겹 씌운다.** 안쪽은 그냥 `AUDIT`이고
`MASH`다.

```
JointBoard
  ├ Done · Total · NeedActors · HereActors   서버가 준 값 (QuestPlay가 매 프레임 주입)
  ├ 안쪽 판을 Tick
  ├ 안쪽 Fill이 1/PerRound를 넘을 때마다 → OnStep() → jointStep 발사
  ├ 안쪽이 통과하면 곧바로 새 판을 연다      ← 릴레이에서 다음 상자가 오는 것
  └ Fill = Done / Total                     내 진척이 아니라 분대 진척
```

**`PerRound = Total / NeedActors`** — 한 판을 다 돌면 딱 한 사람 몫이 나온다.
4인 요구에 12조각이면 각자 한 판씩 돌아 3조각을 낸다.

### 통과를 스스로 선언하지 않는다

조각이 다 차면 서버가 완료로 넘기고 스냅샷의 상태가 바뀌며, 그때 판이 닫힌다.
개인 판은 통과 시 `questCleared`를 보내지만 합동은 보내지 않는다.

### 제한 시간이 없다

`TimesOut => false`. 합동의 제한은 **시간대 잔여 시간**이고, 그건 이미 시간대
종료(`endPhase`)가 잠그는 것으로 걸려 있다. 판이 따로 실패를 선언하면 규칙이
두 곳에 살게 된다.

### 인원 미달이면 손이 안 먹는다

```
var state = Short ? BoardState.Running : _inner.Tick(dt, input);
```

게이지가 안 차는 것을 보여주는 것보다 **아예 못 만지게** 하는 편이 "인원을
모아라"를 빨리 읽힌다. 판 위에 띠가 뜬다 — `인원 미달 — 1/2 · 혼자서는 한
조각도 오르지 않는다`.

### 조각 띠가 이 판의 주인공이다

본문 맨 위에 `Total`칸짜리 띠를 그리고 채워진 칸을 강조색으로 칠한다.
안쪽 판은 그 아래에 들어간다. 남이 채우는 것이 실시간으로 보이는 자리다.

## 아직 아닌 것

QST-01이 적어둔 협동 장치는 넷인데 **하나만** 들어갔다.

| 장치 | |
|---|---|
| 참여 인원 미달 시 진행 정지 | ✓ |
| 역할 게이트 — 행정병만 난로 밸브 | ✗ |
| 공동 부하 — 2인 들것, 느린 쪽 속도 | ✗ |
| 정보 비대칭 — 한 명만 보고 다른 사람이 입력 | ✗ |

남은 셋은 **사람마다 화면이 달라야** 한다. 지금 구조는 모두가 같은 판을 보고
같은 조각 통에 담는 것이라, 여기서 더 가려면 서버가 "누가 무엇을 보는가"를
알아야 한다 — 조각 하나에 `role`이나 `ownerId`를 붙이는 정도가 다음 걸음이다.

그리고 **아직 한 번도 눌러보지 않았다.** sim 테스트와 C# 컴파일은 통과했지만,
합동 판이 실제로 뜨는지는 오후 칸에 요구 인원이 같은 구역에 서 있어야 볼 수
있어서 확인하지 못했다.
