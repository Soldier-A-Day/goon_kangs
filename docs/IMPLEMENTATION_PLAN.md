근거 문서: `SAD-GDD-001 v0.9` (아티팩트 기반)
대상 범위: **규칙 엔진(sim) + 권위 서버 + 웹 셸**. Unity 트랙은 이번 계획에서 제외하되, 경계(프로토콜)는 지금 확정한다.

## 0. 이 계획의 전제

| 항목 | 결정 | 근거 |
|---|---|---|
| 구현 범위 | `packages/sim` + `services/gameserver` + `apps/web` + DOM 디버그 클라이언트 | 기획서 ARCH-02 — 클라이언트는 판정 로직을 갖지 않으므로 Unity 없이도 게임 규칙 전체가 성립·검증 가능 |
| 리포 구조 | npm workspaces 모노레포 | ARCH-02의 "sim 단일 소유" 경계를 코드 규율이 아니라 패키지 의존성으로 강제 |
| Unity | 제외 (프로토콜 스키마만 선확정) | M0 검증 질문 "하루 판정 구조만으로 재미가 있나?"는 3D 없이 답할 수 있다 |

**Unity 없이 검증 가능한 것 / 불가능한 것**

- 가능: 하루 루프, 점호 판정, 온도 밴드 셀렉터, 퀘스트 배정, 하달, 후송·NPC 대리, 계급 심사, 협동 4패턴 중 3개(동시 조작 / 순차 릴레이 / 정보 전달)
- 불가능: 공동 부하(들것·텐트), 행군 대열, 9초 방독면 미니게임, 4인 60fps·100분 힙 게이트(18.0)
  → 이 항목들은 **인터페이스만 뚫어두고** Unity 트랙 착수 시 채운다.

```

```

`apps/web`이 `packages/sim`을 참조하지 못하게 막는 것이 이 구조의 핵심이다. 참조가 가능해지면 클라이언트가 판정을 예측하기 시작하고, ARCH-02가 무너진다.

1. `src/`, `public/`, `next.config.ts`, `tsconfig.json`, `eslint.config.mjs`, `postcss.config.mjs`, `next-env.d.ts` → `apps/web/`으로 이동

5. 루트 `tsconfig.base.json` + 패키지별 `extends`, `sim`/`protocol`은 `noEmit: false`로 빌드 산출

## 2. `packages/sim` — 규칙 엔진 (최우선)

기획서의 모든 수치가 여기 한 곳에만 존재한다. **결정론이 생명이다.**

### 2.1 형태

```ts
// 단일 진입점. 순수 함수. Date.now()·Math.random() 사용 금지 (ESLint no-restricted-globals로 차단)
export function step(state: RunState, event: SimEvent, rng: Rng): StepResult
export function createRun(config: RunConfig, seed: number): RunState
```

- 시간은 이벤트로 들어온다 (`{ type: "tick", elapsedMs }`) — 서버가 주입, sim은 시계를 모른다
- RNG는 시드 주입(mulberry32 등). 같은 시드 + 같은 입력열 = 같은 결과가 테스트로 보장되어야 한다
- `StepResult = { state, effects[] }`, effects는 서버가 소비할 부수효과 선언(스냅샷 갱신, 사운드 큐, 로그)

### 2.2 데이터 테이블 (코드 아님 — JSON)

ARCH-02 "빌드 없이 밸런싱" 원칙. 전부 `packages/sim/data/`.

### 2.4 불변식 테스트 (기획서 수치를 그대로 assert)

이 테스트들이 밸런스 회귀를 막는 장치다.

- `curriculum.json`의 필수 총합 = **76건**
- 4인 × 18일 판정 대상 = **302건**
- 하루 판정 총량 = **17건** (개인 필수 4.2×4 + 합동)
- 훈련 체크포인트 1개 = 필수 1건 → **D-17: 7 = 체크포인트 5 + 보직 퀘스트 2**
- 구제 3회 + 개인 정확도 98% → 완주율 **15%±3%p** (10.0 표)
- 초기 인원 미달 방(ROLE-03)에는 군기 −3/일이 부과되지 않는다
- 같은 시드로 1000회 재실행 시 결과 동일 (결정론)

## 3. `packages/protocol` — Unity 경계 선긋기

지금 Unity를 안 만들어도 **이 패키지는 지금 만든다.** 나중에 만들면 서버가 이미 자기 편한 형태로 굳어 있어 스키마가 서버 내부 타입의 복사본이 된다.

- zod 단일 정의 → `z.infer`로 TS 타입, `zod-to-json-schema` → JSON Schema → (후일) quicktype으로 C# 클래스 생성
- **서버→클라**: `Snapshot`(10Hz, 델타), `Event`(판정 결과·방송·퀵커맨드)
- **클라→서버**: `Intent`만 (`move`, `interact`, `quickCommand`, `assignChore`, `vote`, `chat`)
- 스냅샷에는 **판정에 필요한 원자료를 넣지 않는다** — 계산된 결과만. 클라가 판정을 재현할 수 있으면 언젠가 재현한다

## 4. `services/gameserver` — 권위 서버

### 4.1 배포 형태 (기획서에 없는 결정 — 여기서 확정)

Next.js 16 Route Handler는 WebSocket을 지원하지 않는다 (`node_modules/next/dist/docs/01-app/02-guides/backend-for-frontend.md:927` — "connection closes on timeout, or after the response is generated"). 또한 20Hz 룸 루프는 상태를 든 **장수 프로세스**가 필요하다.

→ **웹 셸은 Vercel, 게임 서버는 상시 구동 Node 프로세스(Fly.io/Railway/자체 호스팅)로 분리한다.** 로컬 개발은 `localhost:3000`(web) + `localhost:8080`(ws).

### 4.2 룸 루프

```
20Hz tick → sim.step(state, {type:"tick"}) → effects 처리 → 10Hz마다 델타 스냅샷 브로드캐스트
```

- 1방 = 1분대 4인 고정, 6자리 초대 코드
- 입력 검증: 거리(구역)·상태·쿨다운 서버 측 확인. 판정 로직은 클라에 존재하지 않음
- 상태 저장은 인터페이스 뒤에 둔다 (`RunStore`) — 초기 인메모리, 이후 Redis 어댑터로 교체해 24시간 이어하기
- 이탈 → **이탈 대리**(한도 없음, 장기) / 후송 → **후송 대리**(인수 한도 2건) — 두 경로를 같은 파이프라인, 다른 정책으로

### 4.3 위치 모델 — 3D 없이 "동선"을 표현하는 방법

기획서 6.1은 "공통 일과의 시간 비용 대부분이 이동"이라고 못박는다. 3D가 없어도 이 비용은 지금 모델링해야 한다.

→ **구역 그래프**를 도입한다. 노드 = 생활관·연병장·창고·식당·초소·훈련장·의무실·보일러실, 에지 = 이동 소요 초.
플레이어 위치는 `{ zone, arrivingAt }`. 상호작용은 해당 zone에 있어야 가능.

Unity가 붙으면 클라가 좌표를 보내고 서버가 zone으로 매핑할 뿐, **sim의 규칙은 한 줄도 바뀌지 않는다.** 이것이 지금 3D 없이 개발할 수 있는 핵심 장치다.

## 6. DOM 디버그 클라이언트 — M0 재미 검증기

Unity 자리에 들어가는 임시 클라이언트. **버릴 코드가 아니다** — 15.0 HUD가 그대로 여기서 만들어지고, Unity는 3D 뷰포트만 가져간다.

- 상단 시간대 바 (잔여 20% 이하 색 경고)
- 좌하단 6스탯 컴팩트 링
- 우측 수첩(Tab) — 내 필수 / 내 선택 / 하달받은 것(누가 넘겼는지) / 분대 합동 4분할
- 하달 창 — 20초, 드래그 배정, 수락 여력 n/2, 예상 군기 변동 실시간
- 퀵 커맨드 라디얼 8슬롯 + 전용 SFX (8.0: 타이핑 없이 18일 완주 가능해야 한다)
- 지도(M) = 구역 그래프. 노드 클릭으로 이동, 이동 타이머 표시
- 상호작용 = 홀드 프롬프트. "2인 필요 — 현재 1명" 명시

**검증 질문**: 이동 + 홀드 + 판정만 있는 상태에서 하루 루프가 긴장을 만드는가? 안 만들면 3D를 얹어도 안 만든다.

|---|---|
| 정규 vs 완화 난이도 기본값 | `RunConfig.difficulty` — 둘 다 구현, 기본값만 후결 |
| 계절 선택 vs 랜덤 | `RunConfig.season: "hot" \| "cold" \| "random"` — 로비 옵션 |
| 1일 실시간 길이 5~7분 vs 3분 | `timeband.json`의 칸당 초 값 — 코드 수정 없이 실측 비교 |
| 하달 공개매칭 정책 | `RoomConfig.choreDelegation: "free" \| "leaderApproval"` |
| 솔로 지원 범위 | ROLE-03 NPC 대리를 그대로 재사용 — 추가 구현 0 |
| 보류자 하한(최소 일병 보장) | `ranks.json`의 플래그 |
