# 발주서 — 더 재미있는 게임을 만드는 순서

`BENCHMARK.md`(조사 16건 종합)의 후속이다. 그 문서는 "무엇이 있는가"였고,
이 문서는 **"무엇을, 어떤 순서로, 어떻게 되면 끝인가"**다.

## 이 발주서의 규칙

모든 발주는 다섯 칸을 채운다. 하나라도 못 채우면 발주가 아니라 소원이다.

1. **목표** — 플레이어가 느끼는 변화를 한 문장으로. "그림자를 넣는다"(작업)가 아니라
   "물건이 바닥에 붙어 보인다"(변화). 이 문장이 검수 기준이다.
2. **완료 판정** — 측정 가능한 조건. "좋아지면"은 판정이 아니다.
3. **검증 방법** — 누가 무엇으로 확인하는가. 코드 검증과 눈 검증을 구분한다.
4. **의존** — 이것보다 먼저 끝나야 하는 발주.
5. **중단 기준** — 이 조건이 나오면 멈추고 보고한다. 매몰을 막는 칸이다.

그리고 대원칙 하나. **모든 단계의 출구는 사람의 플레이다.**
에이전트는 코드가 도는 것까지만 보증한다. 재미있는지는 사람만 안다.
각 단계 끝의 ▶PLAYTEST 게이트를 건너뛰고 다음 단계를 시작하지 않는다.

---

## 플레이테스트 프로토콜 (모든 게이트에서 공통)

- 4인 1세션, 최소 1일차 완주(점호까지). 가능하면 처음 하는 사람 1명 포함.
- 기록할 것: **웃은 순간**(어디서, 왜) / **조용해진 순간**(지루) / **화낸 순간**(불공평)
  / **물어본 것**(게임이 설명 안 한 규칙) / 미니게임별 첫 시도 통과 여부.
- 세션 후 각자 한 문장: "내일 또 하고 싶은 이유가 있었는가."
- 이 기록이 다음 단계의 발주 수치를 정한다. 기록 없는 플레이는 게이트 통과가 아니다.

# A단계 — 재미의 최소 단위를 검증한다

게임의 심장은 미니게임 14종이다. 이게 재미없으면 나머지 전부가 장식이다.
**13종은 한 번도 눌러본 적이 없고 파라미터가 전부 추정값이다.** 여기가 시작이다.

### A-1. 미니게임 14종 전수 플레이 패스
- **목표**: 원형마다 "이 판의 재미는 ___다"를 한 문장으로 확정하고, 그 문장이 실제 판에서 느껴진다.
  (예: SCRUB — "닦는 자국이 남고, 마지막 한 칸을 지울 때 개운하다" / REACT — "늦으면 진짜 늦는다")
- **완료 판정**: 14종 각각 ① 재미 문장 ② 통과 파라미터(추정값→실측값) ③ 첫 시도 통과율 목표
  (필수 일과용 60~80%, 선택 40~60%) ④ "재미없음" 판정 시 폐기/교체 의견. 문서로 남긴다.
- **검증**: 사람이 전부 플레이. 에이전트는 파라미터 노출(치트 콘솔·시간 배속)만 만든다.
- **의존**: 없음. 지금 바로.
- **중단 기준**: 원형 자체가 재미없으면 파라미터를 만지지 말고 보고한다.
  14종을 다 살리는 게 목표가 아니다 — **10종이 좋은 게 14종이 밋밋한 것보다 낫다.**

### A-2. 손맛 최소 세트 (미니게임 튜닝과 같은 판을 만지므로 A-1과 병행)
- **목표**: 누르면 게임이 반응한다. 성공은 기분 좋고 실수는 따끔하다.
- **내용** (게임필 보고서의 수치 그대로, 전부 기존 코드 재사용):
  - 소리 4종(탭·성공·실수·경고) — jsfxr 생성, WebGL 잠금 해제 포함. **저장소 최초의 소리다**
  - `_flash` 패턴을 `Board` 베이스로 승격 → 14종 전체에 색 플래시
  - 결과창 스케일 팝(150ms, 1.15→1.0) / 실수 패널 흔들림(3프레임 4px, 접근성 토글 AND)
  - 판 열림/닫힘에 `GrayscaleFade` 배선(200ms) — 이미 있는 슬롯이다
  - 무반응 4종(SCRUB·PLACE·TRACE·BALANCE)의 Miss 피드백 — 특히 PLACE 극성 반전은
    "되돌릴 수 없는 실수"가 화면에서 크게 읽혀야 한다
- **완료 판정**: 14종 전부에서 성공/실수가 소리+시각으로 구분된다. 흔들림·점멸은 끌 수 있다(3Hz 미만).
- **검증**: 에이전트가 배선, 사람이 "손맛" 판정.
- **의존**: 없음. A-1과 병행.
- **중단 기준**: IMGUI 제약으로 파티클이 과하게 비싸지면 파티클만 빼고 진행(보고서가 이미 예고한 함정).

### A-3. 봇 완주율 0 수정
- **목표**: 자동 시뮬이 하루를 완주한다 — 밸런스를 숫자로 논할 수 있게 된다.
- **완료 판정**: `balance.test.ts` 5건 그린. 완주율이 목표 구간(15~25%)에 들어온다.
- **검증**: 테스트. 이건 순수 코드 검증이다.
- **의존**: 없음. simrunner 봇에 보급 청구·장비 착용 추가(원인은 이미 확정돼 있다).
- **중단 기준**: 봇을 고쳤는데 완주율이 목표 밖이면 **밸런스 자체가 문제**다. 수치를 임의로 만지지 말고 보고.

### A-4. 끊기면 다시 붙는다 (기술 감사에서 나온 치명 결함)
- **목표**: 한 명이 튕겨도 게임이 안 죽는다.
- **근거**: 클라이언트에 재접속 로직이 **0줄**이다. `GameSocket`의 `Closed`/`Failed` 이벤트를
  저장소 어디서도 구독하지 않는다 — 서버는 30초 유예(`DISCONNECT_GRACE_MS`)까지 만들어 뒀는데
  클라가 그 문을 두드릴 줄 모른다. 지금은 순단 한 번이면 그 사람은 사실상 끝이다.
- **내용**: `Closed` 구독 → 지수 백오프 재연결(서버 유예 30초 안에) + "연결 끊김" 배너.
  덤: 로비 진입 시 `/health` 핑 1회(Render 슬립 깨우기 — HANDOFF에 적혀만 있던 30분짜리 수정).
- **완료 판정**: 게임 중 네트워크를 강제로 끊었다 붙였을 때 30초 안에 복귀하고, 화면이 그동안 상태를 말한다.
- **의존**: 없음. **협동 게임에서 이게 없으면 B단계 전체가 모래 위다.**

**▶PLAYTEST A**: 4인이 1일차를 논다. 질문 하나 — "미니게임이 또 하고 싶은가."
여기서 No면 B로 가지 않는다. 심장이 안 뛰는데 옷을 입힐 이유가 없다.

# B단계 — 함께라서 좋은 순간을 만든다

우리의 유일한 차별점. 조사 넷이 독립적으로 같은 곳을 가리켰고,
좀비고 침체기를 살린 것도 4인 협동이었다. JOINT.md에 설계가 이미 있다 — 빚을 갚는 단계다.

### B-1. 정보 비대칭 합동판
- **목표**: 화면을 서로 불러줘야 깬다. **대화가 강제로 발생한다.**
- **내용**: SEQ·TRACE 원형의 합동판에서 한 명은 정답만, 다른 한 명은 조작만 보이게.
  조각에 `role` 필드(JOINT.md의 미구현 항목).
- **완료 판정**: 2인이 말 없이는 못 깨고, 말하면 깰 수 있다. 실제 2인 테스트로 확인.
- **의존**: A게이트 통과.
- **중단 기준**: 서버 프로토콜 변경이 스냅샷 구조를 흔들면 설계 재검토 후 보고.

### B-2. 위기와 구조 — 실패에 소셜을 얹는다
- **목표**: 쓰러지는 동료를 **내가 살릴 수 있다.** 혼자 조용히 실려 나가는 게임이 아니게 된다.
- **내용**: 컨디션 붕괴 직전 "위기" 상태(제한 시간) → 동료가 응급처치 미니게임으로 구조.
  실패하면 후송(기존 규칙 그대로 — **긴장을 물타기하지 않는다**). 의무병은 구조가 더 빠르다.
- **완료 판정**: 위기→구조 성공/실패 양쪽 경로가 4인 세션에서 실제로 발생하고, 구조 순간에
  "고맙다"는 말이 나온다(플레이테스트 기록으로 확인 — 진심이다, 이게 판정 기준이다).
- **의존**: A게이트. sim 규칙 추가라 A-3(봇) 이후가 안전하다.
- **중단 기준**: 위기 상태가 밸런스를 흔들어 완주율이 구간을 벗어나면 수치 조정 대신 보고.

### B-3. 정형 문구 소통 + 역할 게이트 + 공동 부하
- **목표**: 같은 방에 있는 사람에게 **말을 걸 방법이 생긴다.** 자유 채팅의 트롤링 없이.
- **내용**: quick-phrase 6~8종("손 좀 빌려주십시오"·"먼저 갑니다"·"집합") + 상황 자동 말풍선.
  역할 게이트(특정 조각은 특정 보직만) · 공동 부하(2인 짝, 느린 쪽 속도) — JOINT.md 나머지.
- **완료 판정**: 4인 세션에서 quick-phrase가 실제로 쓰이고, 보직 선택이 "이름표"가 아니게 된다.
- **의존**: B-1과 병행 가능.

### B-4. 구제권을 자동 상쇄에서 "발동하는 행동"으로 (설계 어긋남 — 대조로 확인됨)
- **발견**: 기획서의 구제권 3장은 총량만 코드와 같고 메커니즘이 다르다. 기획서는
  **분대장이 직접 발동**(위기 시 퀘스트 1개를 필수→선택 강등, 2회)과 **간부 구제권**(신뢰도 최고
  간부가 저녁 대화로 발동, 1회)인데, 코드는 판정 시각에 **아무 행동 없이 자동 상쇄**한다.
  "썼는지도 몰랐다" 신고의 근본 뿌리 — 표시 누락이 아니라 발동이라는 행위 자체가 없다.
- **목표**: 구제는 분대장이 **결단하는 순간**이 된다 — 선택의 무게(아이작 조사)와 분대장 역할
  (좀비고 조사)을 한 장치로.
- **1차(완료·배포됨)**: 자동 상쇄 사실을 판정 화면에 주황/빨강으로 명시.
- **2차(이 발주)**: 기획서대로 발동형으로 재설계 — 분대장이 어느 퀘스트를 봐줄지 고르고,
  간부 구제는 신뢰도 시스템(E-2)이 화면에 노출된 뒤에.
- **의존**: E-2(신뢰도 노출)와 B-3(분대장 역할). 밸런스 영향이 크므로 A-3(봇) 이후 수치 검증.

**▶PLAYTEST B**: 질문 — "혼자 할 때보다 넷이 할 때 확실히 좋은가." 그리고 **웃은 순간이 있었는가.**

# C단계 — 실패가 다음 판을 만든다

아이작 3단계. 데이터가 전부 이미 있고 선만 없다 — 이 단계는 발명이 아니라 배선이다.

### C-1. 실패의 언어화
- **목표**: 졌을 때 **왜 졌는지 안다.** "다시 하면 이길 수 있겠다"는 생각이 든다.
- **내용**: `HudEnding`에 `firstFailure` 수치 노출("D조건: 위생 18/20 — 3일차 세면장 미완료가 결정타").
  구제권 사용·잔여를 판정 화면에(이미 발주됨 — 진행 중). 런 요약 헤드라인
  ("한파 속 물자 부족 D-5 완주") — `summarizeRun()`에 문구 생성.
- **완료 판정**: 퇴소 화면만 보고 다음 판 전략을 말할 수 있다(플레이테스트에서 실제로 물어본다).
- **의존**: 없음. **A와 병행 가능.**

### C-1b. 값싼 정서 다섯 (내러티브 조사 — 전부 "계산돼 있지만 안 나가는 값"을 문장으로)
발견: **하달 시스템이 이미 Papers Please급 장치다.** 짬 때리기가 코드로 완성돼 있는데
(하달 군기 −2 · 거부권 · 3일 연속 시 정신력 회복 −30%) 화면엔 아이콘 하나뿐이다.
1. 하달·거부 순간 말풍선 1줄 + 종료 화면에 하달 장부("하달을 제일 많이 준 사람 OOO")
2. 점호 실패를 소대장 대사로 — 조건 A~D별 문구("기본이 안 됐다" / "왜 미리 말 안 했나")
3. 후송 순간 남은 3인 화면에 한 문장("OOO가 실려 나갔다. 남은 셋이 그 몫까지 채운다")
4. 돌발 14종 앞에 1~2문장 사건 텍스트("행정반에서 전화가 왔다. '지금 바로 오세요.'")
5. 무전 상태를 역할별로 다른 문장으로 — 통신병만 "네가 못 고쳐서 끊겼다"를 안다
- **완료 판정**: 다섯 전부 규칙 무변경, 텍스트·연출만. 합계 대사 60~80줄.
- **경계** (내러티브 조사에서 확정): 실존 부대·사건 금지, 가혹행위를 미니게임으로 만들지 않기,
  가해자 이분법 금지(상급자도 눌리는 구조 안에 있다), 혐오 은어 배제,
  톤은 D.P.가 아니라 신병·Finnish Army Simulator 쪽(블랙유머 완충 — 반복 플레이와 맞는 무게).

### C-2. 실패가 여는 것
- **목표**: 진 판도 뭔가를 남긴다. "한 판 더"가 이유를 갖는다.
- **내용**: `unlocks` 게이트에 실패 유형 조건 추가(같은 조건 3회 실패 → 그걸 다루는 일과/버프 해금).
  `RunRecord`를 런 생성 시점에 읽어 시작 조건에 반영 — **가장 값싼 단일 연결 고리.**
- **완료 판정**: 일부러 3번 진 뒤 4번째 런이 실제로 다르다.
- **의존**: C-1. 방 메타 저장 위치 결정 필요(Redis 방 단위 vs Supabase 계정 단위 — **이건 내 결정 사항, 착수 전에 정한다**).

### C-3. 매 런이 다른 이유
- **목표**: 같은 부대인데 이번 주는 다르다.
- **내용**: 런 시드에 상관 성향·동기 성격·계절 프리셋. 원형 14종별 숨은 개체 보정(±10%, sim 소유,
  전역증서에서 사후 공개). 물량이 아니라 **조합의 곱**에 투자한다.

# E단계 — 게임이 말한다

오늘 버그 넷(구제권 침묵·판정 화면 삼킴·범례 거짓말·문 없는 방)의 공통 뿌리를 구조로 막는다.
전담 감사가 sim 20개 파일 + 프로토콜 + Unity를 3층으로 교차검증해 **침묵 판정 23건**을
파일:줄 근거와 함께 확정했다(감사 보고서 원문 참조). 심각도 상위:

1. **입력이 씹히는데 씹혔다는 신호조차 없다** — `conditionCritical`(스태미나 0 즉시 후송 전조)과
   `delegationRefused`(하달 거부 사유 9종)를 서버가 **명시적으로 버린다**(`snapshot.ts:229-230`).
   하달 버튼을 눌러도 아무 일도 안 일어난 것처럼 보인다 — 최악의 패턴
2. 구제권 (수정 진행 중)
3. **간부 신뢰도 3트랙이 프로토콜 스키마에 아예 없다** — 승급 축의 절반이 네트워크에 실리지도
   않고, 그걸 쓰는 `bestOfficer`/`strictestOfficer`는 죽은 코드다
4. 후송 복귀 = 계급 리셋·점수 0·재활 2일이 통보 없이 적용
5. `log` 이펙트(경고·근신 설명문) — 프로토콜에 있는데 Unity가 참조 0건. "있는데 배선 안 됨"의 교과서
6. 열사병엔 카운트다운이 없는데 동상엔 있다 — 같은 게임이 두 위협을 다르게 대우

### E-1. 즉시 배선 (프로토콜에 이미 실려오는데 화면만 없는 것들)
`Hud.cs OnEvent`에 토스트 case 추가: `MemberReturned`("복귀 — OOO, 이병으로")·
`ChoreReassigned`·`SupplyClaimed`(품목 리스트)·`ForcedSleep`·`FrostbiteRelieved`·`Log`(신규 case).
구제권 경고 문턱을 0장→**1장**으로("다음 미달은 즉시 퇴소"). 열사병에 동상과 같은 mm:ss 게이지.

### E-2. 서버 수정 필요
`conditionCritical`·`delegationRefused`를 버리지 말고 흘린다(거부 사유를 화면에).
간부 신뢰도를 프로토콜에 싣고 승급 화면에서 `복무점수+신뢰보너스` 두 줄로 분해.
군기 정산을 최종값 한 줄이 아니라 항목별 델타로(스탯 6종이 이미 쓰는 틀 재사용).

### E-3. 수첩에 "오늘의 기록" 탭
그날의 이펙트를 시간순 로그로 — RimWorld식 일지. 서버가 이미 이펙트를 큐잉하므로 배선 작업.

**숨김의 원칙 (감사 결론 그대로 채택):**
게이지가 줄었으면 왜 줄었는지, 입력이 거부됐으면 왜 거부됐는지, 되돌릴 수 없는 일이 벌어졌으면
그 순간 말한다. **숨겨도 되는 것**: 보직별 정보 비대칭(행정병만 아는 날씨 — 협동의 재미다),
안티치트 임계값, 확률의 소수점(방향과 원인은 알린다). **숨기면 불신이 되는 것**: 희소 자원의
소모, 비가역 페널티, 시도했지만 실패한 행동의 사유, 진행 중인 위협의 남은 시간.

**팀 관례로 못박을 것 — `Effect` 타입을 새로 만들면 그것을 화면 문구로 옮기는 매핑이
같은 커밋에 있어야 한다.** 오늘 커밋(`0d07da4`)이 실제로 이 원칙으로 다섯 건을 고쳤다.

- **자동 판정은 반드시 흔적을 남긴다** — 예고(일어나기 전) 또는 통보(일어난 순간) 또는 일지(사후) 중 최소 하나.
- **숨겨도 되는 것**: 아직 안 일어난 것의 확률, 발견의 재미가 있는 내용물.
- **숨기면 불신이 되는 것**: 이미 일어난 판정, 소모된 자원, 플레이어 손해의 원인.
- 수첩(TAB)에 **오늘의 일지** 페이지 — 그날 일어난 자동 판정을 시간순으로.

**완료 판정**: 감사 목록의 심각도 상위 항목 전부가 세 채널 중 하나로 노출된다.
플레이테스트에서 "왜 이렇게 됐지?"라는 질문이 나오면 그 항목은 미완이다.

### H-4. 접근성 (감사 완료 — 토글 7개 중 3개가 죽어 있다)
"만들었는데 안 이어진 것" 패턴이 여기도 있다:

   `HudTheme.Fit()`이 참조하지 않는다. 반나절. **최우선**

4. 점멸은 전부 WCAG 3Hz 안쪽으로 확인됨(문제 없음). 소리 도입 시 시각 신호를 같은 커밋에 —
   접근성 태그는 판매에 실증 효과가 있다(색각 모드 이틀 작업으로 도달 관객 8% 증가 사례)
