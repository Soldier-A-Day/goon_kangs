# SOLDIER : A DAY — Unity 클라이언트

기획서 ARCH-01/02/03에 따라 **게임 세션 표시만** 담당한다. 규칙은 여기에 없다.

**2D 탑다운 3/4 뷰다** (SAD-ART-001 §1.1). 부대 본영이 도로로 이어진 **하나의
심리스 맵**이고, 배치는 도면 `files-4/PLAN_01~04`(SAD-ART-002)를 따른다 —
244×224 타일, 1타일 = 0.5m, 구역 36개 — 부대 본영 26 + 훈련장 10.

## 구역 이동은 걸어서 한다

메뉴에서 목적지를 고르는 방식이 아니다. **문을 지나가면 옮겨진다.**

- 동(棟)은 외벽으로 둘러싸이고, 방은 복도로 통하는 문을 하나씩 갖는다.
  문이 **유일한 통로**라 복도를 지나는 것 말고는 다른 방에 갈 방법이 없다
- 경계를 넘으면 클라이언트가 `move { onFoot: true }`를 보내고, 서버는
  **인접 구역인지 확인한 뒤**(`zones.ts`) 이동 소요를 0으로 둔다 —
  걷는 데 이미 시간을 썼기 때문이다. 인접 검증이 없으면 순간이동으로
  §6.1의 동선 비용을 통째로 건너뛸 수 있다
- **방 하나가 곧 서버 구역이다.** 예전에는 서버가 8구역(`barracks`·
  `drillGround`…)만 알고 아트가 방 25개를 따로 들고 있었다. 그러면 같은
  사실이 두 곳에 살면서 반드시 어긋난다 — 실제로 퀘스트 17건에서 서버 구역과
  방이 서로 다른 건물을 가리켰고, "세면장 청소"를 생활관에 선 채로 끝낼 수
  있었다. 지금은 `packages/sim/data/zones.json`이 구역을 소유하고
  `basemap.py`가 그 표대로 그려졌는지 매번 검사한다 (`_assert_matches_sim`)
- 그래서 **이정표**가 필수다(`Signpost`). 목록에서 고를 때는 이름이 목록에
  있었지만, 걸어서 옮기는 지금은 문 옆에 적혀 있지 않으면 문을 하나씩
  열어보며 부대를 외우게 된다. §6.1의 시간 비용은 동선이지 수색이 아니다

`travelRemainingMs`는 이제 NPC 대리와 헤드리스 시뮬(`simrunner`)에만 붙는다 —
그쪽에는 맵이 없어서 격자 거리로 계산한 소요를 그대로 문다.

## 하이브리드 해상도 — 이 클라이언트의 핵심 결정

§2.1이 정한 두 레이어를 **섞지 않는다.**

| 레이어 | 방식 | 규격 |
|---|---|---|
| 월드 (타일맵·캐릭터) | 픽셀 퍼펙트 | 논리 해상도 **640×360**, PPU **32**, Ortho Size **5.625** |
| UI (HUD·창) | 네이티브 | 레퍼런스 **1920×1080**, 벡터로 그림 |

그래서 HUD 좌표는 전부 1920×1080 기준이고 확정 목업(`files-3/`) 실측값이다.
월드가 640×360으로 뭉툭해도 글자는 선명하다.

## 2D 에셋 파이프라인

에셋 파일 대신 **에셋을 만드는 코드**가 저장소에 있다. 한 번에 다 뽑는다:

```
python3 tools/sprites/generate.py
```

산출은 전부 `Assets/Art/2d/` 아래로 간다.

| 폴더 | 내용 |
|---|---|
| `palettes/` | §4.2 32색 스와치 — 픽셀 아티스트 지급용 |
| `chars/` | §5 캐릭터 8레이어 × 변형 시트 49장 (셀 32×48) |
| `tiles/` | §6 바닥 10종 · 벽 5종 × 오토타일 16장 |
| `props/` | §6.2 `TM_Object` — Y-sort 대상이라 Tilemap이 아니라 개별 스프라이트 |
| `art2d.json` | 씬 빌더가 읽는 색인 |
| `base_map.json` | 부대 본영 — 구역 26종 + 타일 레이어 + 문 + 상호작용 지점 |

생성기는 **팔레트 밖 색을 검사한다.** §4.2가 "팔레트 외 색 사용 금지"라고
못박은 이유는 온도 밴드 그레이딩(§4.3)이 팔레트를 통째로 밀어내는 방식이라
원본이 흔들리면 6밴드가 전부 어긋나기 때문이다. 규칙을 문서에만 적어두면
지켜지지 않으므로 산출물에 대해 실제로 검사한다.

Unity 없이 눈으로 확인하려면:

```
python3 tools/sprites/preview.py preview.png      # 캐릭터 · 타일 · 소품
python3 tools/sprites/mappreview.py map.png 13    # 부대 전체 배치 (도면과 나란히 놓고 본다)
```

맵 오소링(`basemap.py`)은 도면대로 **손좌표로 깐다.** 자동 배치는 도면이
없을 때의 방법이고, PLAN 01이 어느 동이 어디에 서는지 그려버린 이상 그
그림이 진실이다. 대신 구역이 겹치면 생성기가 그 자리에서 멈춘다 —
손좌표를 까는 이상 겹침은 반드시 생기고, 겹치면 바닥이 나중에 칠한 쪽으로
덮여 코드와 화면이 조용히 달라진다.

## 씬 생성

```
Unity -batchmode -quit -projectPath unity \
  -executeMethod SoldierADay.EditorTools.BaseScene.CreateScene
```

에디터에서는 메뉴 **SOLDIER → 부대 본영 2D 씬 생성**. 산출은
`Assets/Scenes/Base.unity`이며 씬을 손으로 만들지 않는다 — 배치가 바뀌면
다시 만들면 되고, 왜 그 모양인지가 코드에 남는다.

렌더링 주의 네 가지 (전부 실제로 겪었다):

- `sortingOrder`는 **부호 있는 16비트**다. ±32767을 넘기면 래핑되어 지면이 위로 올라온다.
- 씬 카메라는 **URP 2D 렌더러**를 쓴다(`Assets/M0/URP_Renderer2D.asset`).
  3D용 UniversalRenderer로 스프라이트를 그리면 정렬이 깊이·배치에 뒤섞인다.
- `Tile`과 `VolumeProfile`은 **에셋으로 저장해야 한다.** 메모리에만 만든
  `ScriptableObject`는 씬 저장 시 참조가 끊기고, 타일맵이 있는데 아무것도
  안 그려지는 상태가 된다 — 로그에는 아무 말도 안 나온다.
- `TextureImporterSettings`는 `ReadTextureSettings`가 **기존 값을 담아 온다.**
  `importer.spriteImportMode`만 바꾸고 `SetTextureSettings`를 부르면 덮어써진다.

## 구역 시야 차단 — 2D 전환의 최대 리스크

`ZoneVisibility.cs`가 §1.3-A와 §1.3-C를 함께 들고 있다.

3D 3인칭에서는 벽 너머가 안 보이므로 "무전 두절 → 물리적으로 모여야 정보가
전달된다"(§8.0)가 성립했다. **2D 탑다운은 기본적으로 화면 안이 전부 보이므로,
그대로 옮기면 통신병이라는 보직 하나가 통째로 무의미해진다.**

- `CanSee` — 다른 구역 분대원 스프라이트를 렌더하지 않는다. **무전과 무관하다.**
- `CanTrack` — 미니맵 마커는 무전 상태에 게이팅된다.

둘을 합치면 A와 C가 같은 장치가 되어 통신병이 다시 무의미해진다.
§13.2가 "M1에서 반드시 검증 — M3로 미루면 되돌릴 수 없다"고 적어둔 항목이다.

## 환경 연출 (M2)

기온이 바뀐 것을 **말 안 해줘도 알아채게** 하는 것이 이 묶음의 목적이다
(§13.2 M2 검증 질문). 넷으로 나뉜다.

| 층 | 소유자 | 무엇 |
|---|---|---|
| 색 | `WeatherGrading` | 밴드 6 + 야간 + 탈수 = Volume Profile 8종, 전환 3초 Lerp |
| 화면 | `ScreenEffects` + `ScreenEffectsFeature` | 풀스크린 셰이더 6종 (§9.2) |
| 공기 | `Vfx` | 파티클 12종 (§9.1) |
| 땅 | `SnowCover` | 야외 눈 오버레이 · 제설로 지워진다 (§6.3) |

**셰이더는 강도가 0이면 패스 자체를 건너뛴다.** URP가 주는
`FullScreenPassRendererFeature`를 6개 얹으면 아무 일 없는 프레임에도 블릿을
여섯 번 하므로, 렌더러 피처 하나가 켜진 것만 순서대로 돌린다. 순서가 규칙이다 —
왜곡 → 프레임 → 색. 거꾸로 하면 서리 테두리가 아지랑이를 타고 일렁인다.

**파티클은 셰이프를 돌려서 쏜다.** Box·Cone 셰이프는 자기 +Z로 뿌리는데 2D
직교 카메라에서 +Z는 화면 속으로 들어가는 방향이라, 그대로 두면 눈이 화면
위에 붙박인 채 깊이로만 멀어진다. `velocityOverLifetime`으로 떨어뜨리는 방법은
안 먹었다 — 모듈이 켜지고 값도 저장되는데 알갱이가 스폰 지점에서 꼼짝을 안 했다.

**알갱이 크기는 그림이 정한다.** 파티클 크기 1은 1월드유닛 = 32px인데(§2.1
PPU 32) 알갱이는 3~24px로 그려져 있다. 1로 두면 3px 눈송이가 32px 흰 사각형이
되어 화면이 종잇조각으로 덮인다.

**눈은 제설로 지워진다.** 일과 중 화면에 흔적이 남는 것은 이것 하나다 —
관물대를 정돈해도 게이지만 차지 관물대는 그대로다. 구역별로 묶어 두고
`chore-snow`가 끝나면 그 구역 타일만 지운다. 밴드가 다시 추워지면 되살아난다.

눈으로 확인하려면:

```
Unity -batchmode -projectPath unity -executeMethod SoldierADay.EditorTools.ScreenFxProbe.Run   # /tmp/sad_fx
Unity -batchmode -projectPath unity -executeMethod SoldierADay.EditorTools.VfxProbe.Run        # /tmp/sad_vfx
Unity -batchmode -projectPath unity -executeMethod SoldierADay.EditorTools.SnowProbe.Run       # /tmp/sad_snow
```

`-nographics`로는 못 돈다. 화면을 안 그리는 모드에서 화면 효과를 검사할 수는 없다.

## 훈련 (M3)

훈련 맵 10종을 **별도 씬으로 만들지 않았다.** §6.4가 씬을 나눈 것은 3D 시절
메모리 예산 때문이고, 2D 타일맵에서 40×24짜리 맵은 씬을 가를 값어치가 없다.

| | 어디에 | 왜 |
|---|---|---|
| 탑다운 7종 | 부대 밖 같은 월드 | 카메라·HUD·파티클·시야가 전부 그대로 돈다. 정문으로 **걸어 나간다** |
| 사이드뷰 3종 | 같은 월드의 별도 무대 | 중력 방향이 다르다. §6.4가 직접 "무대 하나를 공유"하라고 적었다 |

그날의 훈련장은 **서버가 정한다**(`sim/training.ts`). D-15는 밴드가 혹한기와
혹서기를 가르고, D-12·13은 기초와 종합이 다른 코스다.

사이드뷰(`LaneRun`)에서 **전진은 자동이고 플레이어는 속도만 정한다.** 20km를
직접 걷게 하면 그냥 지루한 이동이 되고, 그게 3D 원안이 실패한 지점이다.
페이스 게이지는 **가운데가 안전한** 유일한 막대라 안전 구간을 칠해서 보여준다.

방독면(`MaskDrill`)은 3단계 QTE다. 단계가 오를수록 창이 좁아지는 것은
**손이 굳는 것**을 조작으로 옮긴 것이고, 틀리면 한 칸 물러선다 — 처음부터
돌리면 마지막에서 틀린 사람이 세 번을 다시 한다.

## WebGL

```
Unity -batchmode -quit -projectPath unity \
  -executeMethod SoldierADay.EditorTools.BuildPlayer.Web -out build/web
```

산출은 `unity/Build/web`이며 **14MB**다(§1.2 예산 25MB). 겪은 것 셋:

- **템플릿은 `PROJECT:SAD`다.** `PROJECT:Default`로 두면 그 이름의 프로젝트
  템플릿을 찾다가 빌드가 통째로 실패한다 — 내장 템플릿은 `APPLICATION:`이다
- **`.br`은 헤더 둘이 다 필요하다.** `Content-Encoding: br`이 없으면 압축을 못 풀고
  `Content-Type`이 틀리면 `WebAssembly.compile`이 거절한다
- **Tab·Space·방향키를 브라우저에서 뺏어와야 한다.** 안 그러면 수첩(Tab)과
  일과표(Space)가 게임 안에서 영영 안 열린다. 에디터에서는 멀쩡해 보인다

## 이 프로젝트가 갖지 않는 것

- **판정 로직** — 점호, 온도 밴드, 퀘스트 완료 판단은 전부 서버(`packages/sim`)에 있다
- **밸런스 수치** — 커리큘럼·군기·복무 점수는 서버의 데이터 테이블에 있다
- **난수** — 기온 롤과 돌발은 서버가 시드로 결정한다

`Assets/Scripts/Generated/Protocol.cs`는 `packages/protocol`의 zod 정의에서
**생성**된다. 손으로 고치지 마라. 다시 만들려면 리포 루트에서:

```
npm run codegen:csharp
```

## 서버가 소유하는 것 — 클라가 유도하지 않는다

무전 상태와 보온 게이지는 **판정이라서** 서버에 있다(`packages/sim`). 한때
클라이언트가 통신병의 상태와 체력에서 유도했지만, 둘 다 틀린 방식이었다.

- **무전**(`radio.ts`) — 분대 공통 값이다. 4인이 각자 유도하면 한 사람은 미니맵에
  아군 마커가 보이고 다른 사람은 안 보인다. 그러면 "무전이 끊겼으니 모이자"는
  합의 자체가 불가능해지고, 통신병이라는 보직이 무의미해진다
- **보온 게이지**(`warmth.ts`) — 0이 되면 이동 −30% · 작업 −20%가 실제로 걸린다.
  체력으로 대신 그리던 시절에는 게이지가 가득 찬 화면을 믿고 난로에서 멀어지면
  UI 때문에 죽었다

클라이언트는 `snapshot.radio`와 `member.warmthRemainingMs` / `member.frostbitten`을
**표시만** 한다.

아직 프로토콜에 없는 것은 둘 남았고, 둘 다 순수 표시용이라 급하지 않다.

| 항목 | 지금 | 필요한 것 |
|---|---|---|
| 합동 퀘스트 단계 (§7.2) | 퀘스트 하나의 진척률만 | 단계별 체크리스트 |

## 서버에 붙기

`GameSocket` + `GameClient`를 같은 GameObject에 붙이고 토큰을 넣는다.
토큰은 웹 로비(`apps/web`)가 발급한다 — Unity가 직접 방을 만들지 않는다(ARCH-02 핸드오프).

```
npm run dev:server   # 게임서버
npm run dev          # 로비에서 방을 만들고 토큰 확인
```
